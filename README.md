# 本地 DDNS 节点调度台

Python 3.10+ 标准库服务，带中文管理网页、SQLite 持久化。完整 VLESS 测活额外需要 `sing-box` 和 `curl`，不会接管现有代理配置。

## 本机启动

```sh
cd /root/ddns-panel
sh ./start.sh
```

浏览器访问 `http://127.0.0.1:8787`。第一次启动生成管理密码，保存在 `data/admin-password`，在本机终端查看该文件后登录。也可通过 `ADMIN_PASSWORD` 环境变量指定至少 12 字符的密码。服务持续运行时，网页可以关闭。

若需要从其他局域网设备访问，在宿主机运行：

```sh
BIND=0.0.0.0 sh ./start.sh
```

访问 `http://部署机器的局域网IP:8787`。只允许受信任的局域网访问此端口；跨网络使用时请通过 HTTPS 反向代理访问，密码和节点参数都属于敏感数据。

## Docker 部署

在项目目录运行：

```sh
docker compose up -d --build
docker compose exec panel cat /data/admin-password
```

浏览器访问 `http://127.0.0.1:8787` 并使用生成的密码登录。镜像包含 curl 和 sing-box，可使用完整 VLESS 测活。若宿主机端口已被占用，可在项目目录的 `.env` 中设置 `DDNS_PANEL_PORT=18902`。远程访问可由宿主机的 HTTPS 反向代理转发到该端口。

SQLite 数据库和密码保存在 Compose 命名卷 `panel-data`，重建容器后仍会保留。迁移已有实例时，先停止原实例，再将一致性数据库备份和密码文件复制到新实例的数据目录，并确保文件归容器 UID 10001 所有。已有自动调度配置会在启动时恢复。请单独保管数据备份。

## 操作

1. 在调度设置录入 Cloudflare API Token。建议仅授予指定 Zone 的 DNS Edit（API 权限名 DNS Write）；每组手动提供 Zone ID，无需列举全部 Zone。
2. 添加自己域名下的完整子域名、对应的 Zone ID、原始 VLESS 链接及独立 IP 池。发布版的简写会补齐示例后缀 `example.com`，实际部署请填写完整域名。先不勾选自动执行，使用“测活”验证候选 IP。
3. 确认结果后启用自动执行。保存启用的组后将在下一个调度 tick（约 1 秒）开始检测并创建或更新 DNS。也可点击“立即轮换”。
4. 复制动态域名节点，导入客户端。仅修改 VLESS 的连接地址；原查询参数、SNI、WS Host 和路径均保留。

Cloudflare Token 只保存在本机 SQLite，API 不返回 Token。数据库及初始密码文件限制为当前系统用户读写。网页会显示节点链接，所以管理密码应妥善保存。

## 调度行为

- 每个子域名独立 IP 池。默认每 3600 秒轮换，按 IP 池顺序选择当前 IP 的下一个可用候选。
- 默认每 5 秒检查当前节点，间隔从上一次检测完成后计算。连续三次检测失败后开始候选检测并尝试更新 Cloudflare DNS，不等待小时轮换。
- 单次请求默认超时 8 秒；失败最多尝试 3 次，完整代理模式会尝试备用 HTTPS 目标，因此总任务时间可能明显超过单次超时。多个子域名并行处理，每组候选并发数默认为 3；最多 32 组独立执行，全局预留 2 个当前节点检测名额，另有 6 个候选检测名额，避免对软路由造成过大负载。组很多或 IP 池很大时会产生排队，检测间隔并非严格实时保证。
- 完整代理测活：每次启动隔离的临时 sing-box HTTP 代理，经候选 IP 上的 VLESS 节点访问 HTTPS 检测目标，2xx 才视为可用，结束后销毁临时进程与配置。
- TCP/TLS 模式只代表对应连接层可用，不验证 VLESS 身份认证、WS 路径或代理转发。用于自动故障切换时建议选择完整代理模式。
- Cloudflare DNS 更新成功后才提交新的当前 IP；全部 IP 失败则保留现有 DNS。写入失败约 30 秒后重试，已有当前节点仍按健康周期检查。
- 默认 DNS only，TTL 60 秒。客户端、递归 DNS 缓存和已有长连接可能继续使用旧 IP，故障切换不是无缝切换。
- 暂停组不会自动执行，但手动测活/轮换仍可以执行。删除组会同步删除完整同名的 Cloudflare A / AAAA 记录，成功后删除本地配置；失败保留本地配置并显示原因。
- 配置持久化在 `data/`；重启后恢复调度。轮换时间是上次成功更新后的间隔，不是整点任务。

## 节点和 DNS 限制

支持 VLESS TCP / WS，security=none/tls，保留 SNI、WS Host/path、fp/alpn 等受支持参数。不支持的参数或 Reality / XHTTP / gRPC 会明确拒绝。每组 IP 应使用相同端口、UUID、TLS 和传输参数；任意其他 VPS IP 无法仅通过替换地址变成同一个节点。

动态域名应与原节点的 SNI/WS Host 分开。例如连接 `node1.example.com`，仍向原节点发送原来的 SNI 和 WS Host。Cloudflare CDN IP 与普通 VPS IP 的可用条件不同，以完整测活结果为准。

每组仅支持单一地址族，最多 512 个 IP。同名多条 A/AAAA、CNAME 或另一地址族记录会拒绝更新，避免保留其他地址导致客户端连接结果不确定。本服务不会自动删除这些记录；使用独立子域名最方便。

软路由若存在透明代理，系统路由仍可能影响检测出口。此服务不更改防火墙或路由规则，若希望严格验证直连，应在软路由现有规则中确保候选 IP 流量按期望出口发送。

## Linux 后台启动

在宿主机执行，服务文件默认路径为 `/root/ddns-panel`：

```sh
cp ddns-panel.service /etc/systemd/system/ddns-panel.service
systemctl daemon-reload
systemctl enable --now ddns-panel
systemctl status ddns-panel
```

## OpenWrt / iStoreOS

将目录放到 `/opt/ddns-panel`，安装与路由器架构相符的 Python 3、sing-box 和 curl（包名及安装方式依固件版本确定）。确认：

```sh
python3 --version
sing-box version
curl --version
```

安装启动项：

```sh
cp /opt/ddns-panel/openwrt.init /etc/init.d/ddns-panel
chmod +x /etc/init.d/ddns-panel
/etc/init.d/ddns-panel enable
/etc/init.d/ddns-panel start
```

此启动项监听所有地址；在路由器防火墙中仅开放给 LAN。管理密码文件在 `/opt/ddns-panel/data/admin-password`。

## 按端口批量导入

“批量导入 · 自动识别端口”支持将 `IP:443`、`IP 8443` 与完整 VLESS 链接混合粘贴。IPv6 可使用 `[IPv6]:端口` 或 `IPv6 空格 端口`。中文冒号也支持。每条地址需带端口；完整 VLESS 未写端口时默认 443。

程序按 443、8443 分池，各池独立去重，同一个 IP 可以同时进入两池。其他端口和无效条目计数提示，不混入池中。

填入基础子域名 `node.example.com` 后，一次保存自动生成 `node-1.example.com`（443）及 `node-2.example.com`（8443），没有地址的端口不会创建。纯 IP 导入需要提供一条 VLESS 模板，程序只替换连接端口，保留其他参数；完整 VLESS 导入默认分别采用各端口首条完整节点作为模板。若 UUID / SNI / 路径不同，应分别编辑两组模板再启用调度。

同名组仅在 Zone ID 和节点参数一致时允许追加 IP，保持原来的启用状态；所有分组通过校验后在一个数据库事务内保存。新增组默认暂停。现有运行域名不会在升级时自动重命名；编辑保存时应用新后缀规则，界面会预览最终名称。旧 DNS 记录不会自动删除。

## 正常池、失效池与复活检测

- 轮换、手动测活或当前节点健康检测失败的 IP 会进入该子域名的失效池，正常轮换和手动切换均不再选择它。
- 连续三次检测失败后隔离，5 分钟后执行第一次复活检测；仍失败时依次等待 30 分钟、2 小时、24 小时，之后每 24 小时重试。成功后回到原子域名、原端口的正常池，保留原 IP 顺序。
- 复活检测只验证节点，不直接写 DNS；启用调度的组如果当前地址失效或尚未同步，会随后按正常调度选择可用地址。
- 暂停自动调度的组仍执行分级复活检测，但不自动更新 DNS。
- 为避免大量失效 IP 阻塞正常测活，复活检测分小批执行。到期地址排队检测，因此检测时间可能晚于显示的到期时间。
- 全部 IP 失效时保留原 DNS 并等待复活，不再高频重复检测失效地址。Cloudflare API 写入失败不等于 IP 不可用，不会因此移入失效池。
- 隔离状态、失效原因、首次失效时间和下次检测时间保存在 SQLite，重启和重复导入不会解除隔离。编辑时 IP 列表包含两池地址；删除一个地址会连同其隔离状态移除。
- 升级时将已有最近测活失败记录移入失效池；迁移不会重复重置复活计时。

## 检测期间保存端口分组

批量端口导入使用独立的短时配置锁，不等待后台测活完成。新增组可立即保存；向同名兼容组追加 IP 后，后台任务写回结果会保留新追加的 IP，并安排后续检测。普通节点编辑、删除、全局设置仍等待当前测活任务完成，避免修改正在使用的节点参数。

## 域名列表固定位置

域名记录采用原位更新，检测结果写入不会改变插入顺序；新分组追加到列表末尾。页面定时获取状态时保留已有卡片和按钮，仅更新变化的文字及属性，保留焦点、IP 池展开状态和池内滚动位置。

## 域名复制和最低延迟优选

点击列表中的域名可复制完整域名。正常 IP 池中显示最近测活耗时。自动周期调度、故障切换和“立即优选”都从本次测活成功的正常候选中选择最低延迟 IP；延迟相同时优先保留当前 IP，避免无意义切换。延迟指当前测活方式的总耗时（完整代理模式包含代理启动及 HTTPS 请求），不是 ICMP ping。手动指定 IP 切换仍按用户所选地址执行。此规则替代早期按列表顺序轮换的策略。

## 已保存 VLESS 模板

在“VLESS 模板”模块提前为完整 VLESS 链接命名保存，支持编辑、删除，模板保存在本机数据库。批量导入可为 443、8443 分别选择模板；优先使用所选模板，其次为临时模板，再使用各端口输入节点。纯 IP 导入需选择或填写有效模板。新增单个子域名也可选择模板自动填入，然后按需修改。修改或删除模板不会改动已经创建的节点组。

## 删除域名与 Cloudflare 同步

删除确认框会明确说明同步清理。程序在对应 Zone 内精确匹配完整域名，只删除 A / AAAA 地址记录，保留 TXT、MX 等其他类型及其他子域名。Cloudflare 记录已不存在时可正常删除本地配置。缺少 Token 或 Cloudflare 请求失败会保留本地配置和失败日志，可再次重试；多条记录部分删除失败时，重试会继续删除剩余记录。

实现参考：[Cloudflare 删除 DNS 记录接口](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/delete/)。

## 2026-11-13 稳定性调整

- 不同域名独立执行；同域名测活、优选和手动切换互斥。全局设置、普通编辑和删除仍在所有任务结束后执行，批量追加继续支持检测期间保存。
- 当前节点检测先于本组全池优选和复活检测；另留 2 个检测名额，避免其他组全池检测占满全部检测资源。同一组的长任务期间仍需等待该组任务结束。
- 单次测活最多尝试 3 次，成功立即结束。确认失败后隔离；复活采用 5 分钟、30 分钟、2 小时、24 小时递增间隔。已有隔离地址保留原到期时间，之后按新规则重试。
- 完整代理测活先请求已配置目标，失败后请求备用目标。缺失依赖、进程启动异常及目标返回异常 HTTP 不会淘汰 IP；失效池遇到此类异常 5 分钟后再试，且不推进退避级别。主备均超时仍可能是节点或本机网络故障，无法仅凭超时可靠区分。
- 面板显示执行中的组数和每组任务状态。
